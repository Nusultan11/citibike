# Один подшаг BikeFlow

1. Прочитать [AGENTS.md](../../../AGENTS.md), проверить ветку, HEAD, remote и изменения.
   По [ROADMAP.md](../../../ROADMAP.md), включая §6, определить текущее состояние,
   зависимости и критерии одного утверждённого подшага. Сверить записи с реальными
   файлами и проверками; не объявлять фазу завершённой по одному подшагу.
2. Прочитать только нужные контракты: [продукт](../../../PROJECT_SPEC.md),
   [архитектура](../../../ARCHITECTURE.md), [данные](../../../DATA_CONTRACTS.md),
   [метрики](../../../METRICS.md), [ML](../../../ML_SPEC.md),
   [эксплуатация и тесты](../../../OPERATIONS.md). При отсутствии обязательного
   источника или зависимости зафиксировать блокер, не подменять их предположением.
3. Реализовать ограниченный объём минимальными изменениями. Сохранить совместимость;
   не добавлять код будущих этапов, зависимости или инфраструктуру без необходимости.
   Блокер останавливает зависимую часть; независимую разрешённую работу завершить.
4. Выполнить применимые проверки и тесты из критериев подшага и OPERATIONS;
   проверить diff, ссылки для документации, отсутствие секретов и лишних файлов.
   Для дефекта добавить регрессионную проверку; неудачи исправить и перепроверить.
   Пропущенные проверки обозначить NOT VERIFIED с причиной, не объявлять их успешными.
5. Обновить единственный журнал ROADMAP §6 компактной записью: дата, этап/подшаг,
   фактический статус, сделанное, команды и результаты, SHA/PR, ограничения и выводы,
   один следующий шаг. Сохранить исходные этапы и требования; не создавать второй журнал.
6. После просмотра итогового diff и staged files зафиксировать проверенный подшаг
   Conventional Commit. При необходимости записать его SHA отдельным коммитом журнала;
   синхронизировать с origin только при разрешении и доступе. Проверить итоговый Git status.
7. Дать отчёт по формату AGENTS.md с фактическими проверками, ограничениями и Git-состоянием.
   Остановиться: следующий подшаг требует приёмки пользователя.
