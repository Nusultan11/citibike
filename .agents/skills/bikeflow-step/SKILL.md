# Полный этап BikeFlow

Один промпт → один полный этап → реализация → проверки → отчёт → независимая
приёмка. Внутренние задачи Codex планирует и завершает самостоятельно, без
обязательных отдельных промптов. Корректирующие промпты допустимы при PARTIAL,
BLOCKED или дефектах приёмки. Отдельная явно запрошенная работа между этапами
не становится новой фазой и не разрешает начать следующий этап.

1. Прочитать [AGENTS.md](../../../AGENTS.md), проверить ветку, HEAD, remote и изменения.
   По [ROADMAP.md](../../../ROADMAP.md), включая §6, определить текущее состояние,
   зависимости и полный DoD утверждённого этапа либо границы отдельной задачи.
   Сверить записи с кодом, тестами и конфигурацией; составить внутренний план.
   Исторический COMPLETED не доказывает независимую приёмку или выполнение новых
   требований. Различать IMPLEMENTED, VERIFIED, NOT VERIFIED и PLANNED по AGENTS.md.
2. Прочитать только нужные контракты: [продукт](../../../PROJECT_SPEC.md),
   [архитектура](../../../ARCHITECTURE.md), [данные](../../../DATA_CONTRACTS.md),
   [метрики](../../../METRICS.md), [ML](../../../ML_SPEC.md),
   [эксплуатация и тесты](../../../OPERATIONS.md). При отсутствии обязательного
   источника или зависимости зафиксировать блокер, не подменять их предположением.
3. Выполнить весь разрешённый объём минимальными проверяемыми изменениями.
   Сохранить совместимость; изменения контрактов сопровождать миграцией и тестами,
   применённые миграции не переписывать;
   не добавлять код будущих этапов, зависимости или инфраструктуру без необходимости.
   Блокер останавливает зависимую часть; независимую разрешённую работу завершить.
4. Выполнить применимые проверки и тесты полного DoD этапа/задачи и OPERATIONS,
   включая негативные и аварийные сценарии по риску;
   проверить diff, ссылки для документации, отсутствие секретов и лишних файлов.
   Для дефекта добавить регрессионную проверку; неудачи исправить и перепроверить.
   Пропущенные проверки обозначить NOT VERIFIED с причиной, не объявлять их успешными.
5. Обновить единственный журнал ROADMAP §6 компактной записью: дата, этап/задача,
   фактический статус, сделанное, команды и результаты, SHA/PR, ограничения и выводы,
   один следующий шаг. Сохранить прежние записи, доказательства и SHA; не выдавать их
   за повторные проверки. Требования менять только в разрешённом объёме, расхождения
   с реализацией фиксировать без подгонки требований; не создавать второй журнал.
6. После просмотра итогового diff и staged files зафиксировать проверенный этап/задачу
   Conventional Commit; неполную работу не объявлять завершённой.
   При необходимости записать SHA отдельным минимальным коммитом журнала;
   синхронизировать с origin только при разрешении и доступе. Проверить итоговый Git status.
7. Дать отчёт по формату AGENTS.md с фактическими проверками, ограничениями и Git-состоянием.
   Остановиться: следующий этап требует независимой приёмки пользователем текущего
   результата и выполнения зависимостей ROADMAP.
