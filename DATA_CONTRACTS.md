# DATA_CONTRACTS — источники, схемы, качество данных

**Назначение:** обязательные правила представления и движения данных. Значение бизнес-показателей вынесено в [METRICS.md](METRICS.md). Как реализовать проверки: [knowledge_base/02_DATA_ENGINEERING.md](knowledge_base/02_DATA_ENGINEERING.md).

## 1. Реальные источники и допущения

| Источник | Что получаем | Частота/ограничение |
|---|---|---|
| Citi Bike trip history | Опубликованные поездки (ZIP/CSV); бывают несколько CSV в архиве | Обновления по факту публикации; не realtime |
| GBFS discovery | Ссылки на feed, версии, `ttl` | Discovery через официальный индекс, без жёстко зашитых дочерних URL |
| GBFS station information/status | Координаты, capacity, текущие bikes/docks и режим работы | Периодический сбор; это не архив прошлых значений |
| Open-Meteo | История погоды, доступные архивные прогнозы | Проверять покрытие, время выпуска, лицензирование |
| Calendar | Час, день недели, holidays, DST | Создаётся локально + актуальный календарь праздников |

**Стартовый скоуп:** последние 24 полностью доступных месяца по NYC; исключение `JC` — как исследовательская граница, а не «повреждённые записи». До загрузки сверить перечень архивов и содержимое. Путь discovery и лицензия: [knowledge_base/01_SOURCES_RESEARCH.md](knowledge_base/01_SOURCES_RESEARCH.md).

## 2. Уровень детализации (grain)

| Dataset | Одна запись | Ключ/инвариант |
|---|---|---|
| `bronze_source_objects` | Один объект/версия источника | `(source_id, object_path, source_version/hash)` |
| `silver_trips` | Одна выбранная каноническая поездка | `ride_id` только после проверки; дубликаты/конфликты изолированы |
| `silver_station_status` | Снимок одной станции в конкретном сборе | `(collection_id, station_id)` |
| `dim_station_history` | Версия характеристик станции | `(station_id, valid_from)`; интервалы не перекрываются |
| `silver_weather` | Локация × час × тип продукта/выпуск | Нет смешения наблюдения и прогноза |
| `fact_station_hourly` | Станция × локальный/UTC час | `(station_id, hour_utc)` |
| `fact_route_daily` | Дата × station_from × station_to | Один уникальный составной ключ |
| `ml_forecasts` | Станция × origin × target_hour × тип × модель | Нельзя перезаписывать прошлые прогнозы без версии |

## 3. Словарь критических полей

**Trip history (современный формат источника):** `ride_id`, `rideable_type`, `started_at`, `ended_at`, `start_station_name`, `start_station_id`, `end_station_name`, `end_station_id`, `start_lat`, `start_lng`, `end_lat`, `end_lng`, `member_casual`. В старых архивах иные имена и семантика; требуются версионные mappings, нельзя бездумно объединять категории старого `usertype` с новой классификацией.

**Silver-derived:** `started_at_utc`, `ended_at_utc`, `duration_seconds`, `source_object_id`, `schema_version`, `quality_status`, `quality_reason_codes`, `processed_at_utc`. `station_id` — строка; неизвестную станцию не выдумывать по координатам без подтверждённой процедуры.

**GBFS:** хранить оригинальный JSON, feed version, source `last_updated`/station `last_reported` где доступны, `received_at_utc`, `ttl`, нормализованные велосипеды/доки и `is_renting`/`is_returning`. Названия полей версии 2.3 и 3.0 различаются — использовать discovery и version-aware mapping.

**Временные правила:** время источника и время поступления — разные сущности. Локальный час Нью-Йорка может повторяться при DST; технический ключ временного бакета хранить в UTC. Неоднозначное исходное время пометить, а не молча интерпретировать.

## 4. Правила проверки и принятия

| Класс | Проверка | Реакция |
|---|---|---|
| Completeness | Обязательные поля, null rates по месяцам/источникам | Сохранить и классифицировать пропуски |
| Uniqueness | Exact rows, duplicate IDs, conflicts | Канонизация только при доказанном правиле; conflicts → quarantine |
| Validity | Время, координаты, категории, неотрицательные counts | Ошибку изолировать или ограничить применение |
| Integrity | Join с историей станций, отсутствие join-explosion | Не публиковать несогласованный Gold |
| Timeliness | Source event/update → ingest → publish lag | Маркировать stale и ограничивать risk/serving |
| Drift | Схема, распределения, доля пропусков по времени | Alert/ревью правил преобразования |
| Reconciliation | Каждому входному ряду назначен итоговый статус; агрегаты сводятся | Блокирующий quality gate |

**Не удалять редкие реальные пики**, не заменять null нулём автоматически, не выводить «нет поездок» из отсутствия наблюдений, не вычислять доход из trip count.

## 5. Preprocessing / EDA контракт

**Data-quality EDA до изменения данных:** schema/drift, строки/ключи, nulls, длительности, время/DST, station/route coverage, категории, география, weather joins, GBFS gaps и train/serve availability. Для проблемы фиксировать `evidence → impact → rule → test`.

**Исследовательский EDA:** изучить station-hour распределения (нули, редкие события, пики), неоднородность и изменение состава станций, недельную/годовую сезонность, пространственные различия, аномалии и сдвиги между периодами. Для каждой гипотезы хранить вопрос, воспроизводимый расчёт/срез, результат, ограничение и способ проверки. Корреляцию не объявлять причинностью.

**ML preprocessing / readiness:** перед feature engineering проверить происхождение и покрытие targets, допустимый ноль против missing observations, долю исключений по периоду/станции, репрезентативность cohort и кратность joins. Преобразования должны быть детерминированными и версионированными, статистики — обучены только на train, source/feature availability — подтверждена на origin. Не заменять пропуски предположениями без проверки.

**Silver:** типизация, сохранение исходного и нормализованного времени, признаки качества, детерминированный dedup, versioned station history, weather provenance. Некорректные случаи → quarantine с `reason` и входным `source_object_id`.

**Публикация:** писáть во временную область, проверять schema/counts/checksums/grain, затем атомарно переключать опубликованную версию. При неудаче прошлую версию оставлять доступной.

## 6. Историческая воспроизводимость

Каждый объект несёт: `source_url`, `retrieved_at`, `checksum`, `source_version`, `pipeline_version`. В Gold — ссылки на партиции Silver и версию трансформации. В ML — `feature_snapshot_id` плюс as-of доступность. Не использовать поздно опубликованные архивы как будто они существовали в момент прошлой симуляции.

**Приёмка:** нет немотивированных исчезнувших записей, конфликтующих ключей и бесконтрольного дублирования на join; неизвестные и неподтверждённые признаки остаются nullable/flagged, а не заполняются догадками.
