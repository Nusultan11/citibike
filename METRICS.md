# METRICS — единые определения показателей

**Назначение:** единственный нормативный словарь метрик для SQL, API, Dashboard и ML-отчётов. Структура таблиц — [DATA_CONTRACTS.md](DATA_CONTRACTS.md), прогнозные ошибки — [ML_SPEC.md](ML_SPEC.md).

## 1. Единицы и фильтры

- **Поездка:** один допустимый опубликованный `ride_id` (либо подтверждённый канонический эквивалент после старых схем).
- **Станция:** `station_id`, не название; изменения места/вместимости — исторические версии.
- **Период:** полуоткрытый интервал `[start, end)`; технические вычисления по UTC, показ месяца/дня/часа по `America/New_York`.
- **Обязательные подписи:** источник, дата актуальности, timezone, область NYC/JC и применённые фильтры. Неполный текущий период не сравнивать с полным без нормализации/пометки.
- **Null ≠ 0**; stale GBFS ≠ наблюдаемая доступность. Исторические поездки ≠ текущий live спрос.

## 2. Основные бизнес-метрики

| Метрика | Определение / формула | Важная граница |
|---|---|---|
| `completed_published_rides` | Число допустимых опубликованных поездок с `started_at` в периоде | Название отражает охват публичного источника, не все спросовые события |
| `departures_s` | Число допустимых поездок со `start_station_id=s`, `started_at` в периоде | Не включает неизвестный старт |
| `arrivals_s` | Число допустимых поездок с `end_station_id=s`, `ended_at` в периоде | Конец поездки может быть в другом периоде |
| `net_trip_flow_s` | `arrivals_s - departures_s` | Не равен изменению наличия из-за перевозок/ремонта |
| `active_stations` | Число станций, допускающих работу в выбранный момент согласно GBFS | Не подменять числом станций с поездками за месяц |
| `average_duration` | `sum(valid duration_seconds) / count(valid durations)` | Никаких отрицательных/невалидных длительностей; знаменатель явен |
| `trip_category_share` | Поездки категории / поездки с известной сопоставимой категорией | Unknown показывается отдельно; старые схемы сопоставлять осторожно |
| `route_volume` | Число поездок по паре start/end station за период | Требует обе известные станции; доля покрытия указывается |

## 3. Метрики доступности (из собранных GBFS)

| Метрика | Определение | Замечание |
|---|---|---|
| `rentable_bikes` | Число доступных велосипедов при `is_renting=true` | Иначе выдачу запрещено считать доступной |
| `returnable_docks` | Число свободных доков при `is_returning=true` | Нельзя использовать только capacity |
| `empty_station_time_share` | Продолжительность валидных интервалов работы с `rentable_bikes=0` / общая наблюдённая валидная продолжительность работы | Не доля JSON-снимков; gaps и stale интервалы исключать/выделять |
| `full_station_time_share` | Аналогично для `returnable_docks=0` | Станция должна принимать возвраты |
| `observed_coverage` | Длительность подтверждённых наблюдений / целевая длительность окна | Отдельно от доступности; длительные интервалы неизвестности не заполнять |
| `status_freshness_sec` | Текущий момент − последняя source timestamp | Имеет значение для доверия к realtime |

Пример: если нет данных о станции 30 минут, нельзя считать эти 30 минут ни пустыми, ни полными. Допустимое межснимковое окно и правила интерполяции утверждаем после EDA.

## 4. Производные показатели и правила агрегации

- **Пики:** по отправлениям и прибытиям отдельно, с одинаковыми интервалами и явной датой.
- **Изменение периода:** `(value_current - value_previous) / value_previous` только при `value_previous ≠ 0`; иначе `N/A` с пояснением.
- **Доли:** пересчитывать из суммарных числителя/знаменателя после фильтра; не суммировать проценты и не усреднять медианы станций.
- **Маршруты:** карта/таблица может включать лишь строки с валидными двумя station IDs; отдельно показывать долю исключений.
- **Районы:** присвоение станции району по исторически корректным координатам; изменение границ/маппинга должно иметь версию.

## 5. KPI для решений (показывать как оценку, не факт)

| KPI | Статус и как проверяем |
|---|---|
| `forecast_departures/arrivals` | ML-предсказание по станции/часу с origin, горизонтом и версией; метрики ошибки в ML_SPEC |
| `empty/full_risk` | Модельная вероятность или симуляционная доля неблагоприятных сценариев за горизонт; требует калибровки |
| `simulated_unserved_rides` | Ожидаемое число неисполненных попыток аренды/возврата **только по предположениям симулятора** |
| `simulated_rebalance_gain` | KPI при no-action/эвристике − KPI оптимизированного сценария на том же потоке случайностей | Не фактическая экономия, если нет полевой проверки |

**Запрещённые подмены:** `trip_volume = revenue`, `net_trip_flow = фактический inventory`, `ML risk = подтверждённый отказ`, `корреляция = причинность`.

## 6. Представление на Dashboard

Главный экран: 2–4 первичных KPI, тренд, текущее состояние сети и очередь рисков. Исторические и realtime показатели визуально и текстово разделены. Все сравнения должны содержать сопоставимый знаменатель/период. Tooltip каждой неочевидной метрики открывает краткое определение из этого документа.

**Тест метрик:** независимый расчёт по контролируемой выборке → сравнение Silver → Gold → API → UI при идентичной области и фильтрах. Для времени использовать тесты DST и границ суток.
