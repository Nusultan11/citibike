# Шпаргалка 07 — симуляция станции и оптимизация перемещений

**Когда открывать:** после получения валидных прогнозов отправлений/прибытий и истории GBFS, перед оценкой рисков и rebalancing. Требования к бизнес-эффекту — [../PROJECT_SPEC.md](../PROJECT_SPEC.md), целевые показатели — [../METRICS.md](../METRICS.md), ML-условия — [../ML_SPEC.md](../ML_SPEC.md).

## 1. Почему прогноз ≠ решение

Прогноз отправлений и прибытий — только вход в расчёт запасов. Для станции с вместимостью `C`, текущим запасом `B_t`, попытками аренды `D_t`, возврата `A_t` и движением персонала `R_t` приближённая схема:

`B_(t+1) = clip(B_t + A_t - D_t + R_t, 0, C)`.

**Но это не готовая модель потерянного спроса:** попытки в реальности ограничены наличием велосипедов и доков; очередность событий внутри часа влияет на потери. Поэтому лучше использовать дискретно-событийную либо достаточно частую пошаговую симуляцию. Ненаблюдаемые попытки аренды требуют допущений и анализа чувствительности.

## 2. План минимального симулятора

1. Начальное состояние каждой станции: bikes, docks, capacity, режим работы, возраст GBFS наблюдения.
2. По временны́м шагам генерировать попытки аренды и возврата из статистической модели прогнозов, с явно заданной неопределённостью.
3. Если нет велосипеда — считать **модельную** неисполненную аренду; если нет места — неисполненный возврат/перенаправление согласно допущению.
4. Добавлять действия перевозки велосипедов с временем прибытия, вместимостью грузовика, доступным запасом и лимитом времени.
5. Повторять на нескольких случайных seeds и сценариях, публиковать распределение результата, а не одно число.
6. Сравнивать no-action, простой порог и оптимизатор на одинаковых сценариях и последовательностях случайных событий.

**Проверка неопределённости:** интервалы/распределения спроса оценивать на независимых временных окнах по coverage и calibration. Без меток реальных отказов вероятность из симуляции не является калиброванной вероятностью фактического отказа. Сначала сравнить с простой пороговой эвристикой.

## 3. Что оптимизировать

Начать с **целевых остатков по станциям** под ограничениями `0 ≤ target_bikes ≤ capacity`, `перемещённые велосипеды ≤ доступный запас`, `суммарный баланс сети согласован`, `парк транспорта/время ограничены`. Затем перейти к маршрутам транспортных средств, если это улучшает результат.

Вариант целевой функции: минимизировать `ожидаемые модельные отказанные аренды + модельные неуспешные возвраты + λ × затраты перемещения`. Коэффициент λ — сценарный параметр, не известная цена компании.

## 4. Проверки, блокирующие вывод

- Перевозка не создаёт и не уничтожает велосипеды (кроме явного сценария выбытия).
- Не загружаем грузовик сверх вместимости, не оставляем станцию с отрицательным остатком и не превышаем свободные доки.
- Состояния станций согласованы с моментом GBFS и статусом `is_renting`/`is_returning`.
- При нулевом спросе оптимизатор не должен предлагать бессмысленную перевозку, если нет отдельной причины.
- Рекомендация не становится «реальным эффектом» без данных о фактически выполненных поездках/маршрутах и экспериментальной проверки.
- Результат чувствителен к неизвестному спросу? Показываем диапазон сценариев и риск непригодности.
